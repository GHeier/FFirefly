# Vertex SIGSEGV Fix Summary

## Problem Identified

The SIGSEGV error in `vertex_shape.py` was caused by a **mesh size mismatch** in the HDF5 files generated by `vertex/from_susceptibility/vertex.cpp`.

### Root Cause

In `vertex.cpp` (line 147-148), the code was:
```cpp
chi.cmf.data.data = vals;
chi.save(file);
```

This approach copied the chi field's metadata (including `mesh`) but replaced only the `data`. The issue:

1. **chi.h5** was generated with `k_mesh = [300, 300, 300]`
2. **vertex.cpp** computed values using `q_mesh = [150, 150, 150]`
3. The saved vertex file had:
   - `mesh = [300, 300]` (from chi)
   - `data.size = 150*150*51 = 1,147,500` (from vertex calculation)
4. This inconsistency (metadata says 300×300 but data only has 150×150) caused segfaults when Python tried to read/interpolate the data

### Additional Issue

Old vertex files like `real_n=0.85_vertex.h5` had dimension/mesh inconsistencies:
- `dimension = 2` (2D system)
- `mesh = [300, 300, 1]` (3 elements instead of 2!)

This mismatch caused crashes in the C++ evaluation code.

## Solution

Modified `/home/g/Research/FFirefly/src/many_body/vertex/from_susceptibility/vertex.cpp` line 147-151:

```cpp
chi.cmf.data.data = vals;
// Update mesh to match the q_mesh used for vertex calculation
if (chi.cmf.data.as_mesh) {
    chi.cmf.data.mesh = vector<int>(q_mesh.begin(), q_mesh.begin() + chidim);
}
chi.save(file);
```

This ensures the `mesh` metadata correctly reflects the `q_mesh` dimensions used in the calculation, and properly handles 2D vs 3D by using only `chidim` elements.
